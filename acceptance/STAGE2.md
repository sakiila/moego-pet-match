## IMPLEMENTATION_PLAN 阶段 2 验收

| 验收项 | 证据 |
| --- | --- |
| 两个请求同时提交同一局只记一次 | `server/__tests__/settle.test.ts`「两个请求同时提交…」：第一个事务提交前停 300 ms 保证重叠；去掉对局行锁后此测试失败、恢复后通过（变异检查） |
| 结算中途失败不留下部分进度 | 同文件「结算中途失败…」：事务内注入失败后结果、个人最好、收集、局数均无变化；恢复后同一局重试成功且只记一次 |
| 已保存但响应丢失，在当前报告重试不重复计数 | 同文件「服务端已保存但响应丢失…」；同编号不同内容返回 409；换身份重试返回 409（不改写归属） |
| 失败只在当前报告重试，离开或刷新不找回 | 浏览器：停掉服务端打完一局 → 报告「暂未确认保存，可在当前报告重试」（[04](stage2/04-report-retryable.png)）→ 重启服务端点「重试保存」→ 已保存，数据库该局只有 1 条结果、局数 +1。冻结结果只存在于报告页内存（`web/src/game/useResultSubmission.ts`），没有持久队列或找回入口（代码审阅，未单独写测试） |
| 已发出的请求在离开后保存成功仍保留真实结果 | 服务端提交与客户端是否还在页面无关（事务提交即生效）；未单独写测试 |
| 重启服务后已保存记录保留 | 浏览器：两次停启服务端后，个人最好 480 与两局结果仍在（数据在 Postgres，不在服务进程） |
| 刷新后读取已保存记录并记住有效身份；失效回选择页；读取失败不当作失效 | 浏览器：刷新直接回门店并显示个人最好（[02](stage2/02-home-after-reload.jpg)）；记住的身份改成已停用账号 → 回选择页并清除；服务端断开 → 「暂时没能读取同事名单，请重试」、身份保留，重试后回门店 |
| 图片经自有域名代理与缓存，浏览器不直连 Slack / R2 | Slack 头像：正式模式下 `/img/avatars/U03FPQWGTN2` 返回 200（PNG，73 KB），第二次走缓存。宠物图：`images.test.ts` 用内存对象存储验证代理、长期缓存头、下架拒绝并清缓存；**真实 R2 未验证** |
