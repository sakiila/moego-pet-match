## 目标与推荐

让玩家向另一位玩家表达一次简单的认可，并让收到认可的人在回到门店时看到累计数量。推荐功能名为「爪爪赞」，界面主动作仍用容易理解的「送个赞 / Like」。

推荐图形为「爱心肉垫」：四颗脚趾肉垫加一颗爱心形主肉垫。它在 20–24px 下依然清晰，并以爱心形主肉垫区别于现有开始营业、普通模式所用的普通爪印。

备选图标为「举爪击掌」与「猫猫抱心」。三种图标分别出独立概念图，沿用既有橙白色、炭黑描边与轻量层次，不在这一轮更换整体视觉语言。

## 规则（待确认的推荐默认值）

- 点赞对象是玩家，宠物和某一局成绩不是点赞对象。
- 同一玩家身份对另一位玩家身份最多送一次；不能给自己点赞。
- 按长期累计处理，不按天重置；普通模式、鱼模式、今日榜和总榜共用同一条点赞关系。
- 按「只能点一次」的要求，推荐首版点赞后不可取消。此处是方案建议，尚未成为已确认规则。
- 对方可以回赞，A → B 与 B → A 是两条独立关系。
- 数量只表示收到的赞数；不加游戏分数、不改变排名、不关联称号解锁。
- 首版不公开点赞者列表，不增加通知入口、红点或弹窗。

## 位置

### 别人的玩家名片

在现有头像、姓名与佩戴称号区域下方，以及最高分／已收集／已营业三列数据上方，插入一个独立横行：左侧「图标 + 收到 12 个赞」，右侧「图标 + 送个赞」。小屏或长英文文本可以将该行分成两行，点赞操作保留至少 44 × 44 CSS px 的触摸区域。

点赞后右侧变为「已点赞」，图标和底色一起改变；数量更新为服务端返回值。查看自己的名片时，同一位置只展示收到的赞，不出现点赞按钮。

排行榜继续通过点玩家打开名片；不在每一行或领奖台增加额外按钮。能打开同一玩家名片的入口都共享状态。

### 自己在门店首页

在右上角头像左侧放一个紧凑的「图标 + 12」浅橙胶囊；头像右下已有称号徽章，保留其空间。胶囊也允许显示 0，加载未完成时显示占位而不是伪造 0。给四位以上数字留宽度，数量采用本地化格式。

点胶囊打开自己的玩家名片，看到完整的「收到 12 个赞」。它是数量查看入口，不是给自己的点赞按钮。当前菜单的称号、打卡下班等操作保持原位。

若头部在 390px 下放不下品牌、语言、胶囊与头像，优先把胶囊紧贴头像下方，不缩小触摸区，不覆盖徽章；具体以选定图稿与实际排版为准。

## 交互状态

| 状态 | 数量 | 操作与反馈 |
| --- | --- | --- |
| 未点赞 | 服务端确认的累计数量，可为 0 | 可点「送个赞」 |
| 提交中 | 保留已确认数量 | 按钮短暂显示「发送中…」，锁定连续点击 |
| 点赞成功 | 使用服务端返回的最新数量 | 显示「已点赞」，按钮保持清晰可见但不可再次提交 |
| 自己的名片 | 累计收到的数量 | 没有点赞按钮 |
| 加载中 | 数量占位 | 暂不允许提交 |
| 加载失败 | 显示「暂时没读到」 | 可重试，不假装为 0 |
| 网络失败／请求超时 | 保留最后确认数量 | 显示「网络开小差了，点此重试」；重试前或重试后重新同步状态，以处理服务端已经写入的情况 |
| 玩家已不可参与 | 保留名片原有不可用提示 | 不能点赞 |

点下时有轻微压缩，成功后肉垫弹一下，数字短促 +1；全过程约 250–400ms，不弹确认框、不整页庆祝、不晃动卡片。减少动态效果时只切换图形和文案。成功前不增加数字，因此失败不会造成虚假的赞数。

## 图标约束

- 爱心肉垫：四趾加心形掌垫，最适合作为常驻数量图标；注意心形缺口在 20px 时仍可辨。
- 举爪击掌：一只朝向观者的短毛爪，有短腕部、橙色肉垫；互动感强，窄小位置的轮廓更复杂。
- 猫猫抱心：简洁猫头与抱住的心形，角色感强；需要更大尺寸，作为备选而非首选。
- 未点赞、提交中和已点赞沿用同一轮廓；不只靠颜色区分状态，还使用「送个赞／已点赞」文字。
- 不用手势点赞或拟人拇指，不把模式标记的普通爪印直接复用为点赞图标。
- 本轮 PNG 为效果参考。选定后优先按项目约定用 SVG 实现，再接入统一 Icon；若要从生成稿直接切 PNG，需另行明确该素材授权，不将概念截图当页面素材。

## 工程落点（后续确认后再实施）

独立保存有向关系 `player_likes(from_player_id, to_player_id, created_at)`，数据库唯一约束为 `(from_player_id, to_player_id)`，并加禁止 self-like 的 CHECK。为 `to_player_id` 建索引支持累计统计。服务端检查双方为当前有效玩家，插入采用冲突忽略，使双击、并发、超时重试和多个入口都只产生一条关系。总数从关系表读取，不维护第二份可漂移的计数。

现有 `PlayerProfileView` 增加 `receivedLikes`、`likedByViewer` 与 `canLike`；自己的 `PlayerView` 返回 `receivedLikes`。读取他人名片需要同时传入当前查看者身份，才能确定按钮状态；普通与鱼模式只影响对局数据，不拆点赞关系。提交返回同一份权威总数和查看者状态。

展示由 PlayerProfileCard 和 PlayerMenu 周边组合；新增一个小型点赞操作组件以及一个只读数量组件，按项目约定登记陈列页。只抽复用所需内容，不调整无关卡片或排行榜结构。

现有项目通过选择同事身份参与，并无已验证的个人登录凭证。因此上述「每人一次」准确含义是「每个玩家身份 ID 一次」；数据库可保证身份对之间唯一，不能额外宣称已防止他人切换身份代点。首版沿用该边界，不在本功能中扩展登录系统。

进入门店、打开名片及页面重新获得焦点时刷新相关数量；无需为这项功能引入实时推送或持续轮询。

## 实施后的必要验收

后端覆盖：正常点赞、自己点赞、重复与并发请求、互相点赞、无效身份，以及跨模式共用；重复请求不加数。前端陈列覆盖：未点赞、已点赞、自己、0、大数、长姓名、中英文、加载和失败；390 × 844 下真实入口检查；确认头像徽章不重叠、排行榜点击仍可用、网络重试不会重复计数、减少动态效果可用。
