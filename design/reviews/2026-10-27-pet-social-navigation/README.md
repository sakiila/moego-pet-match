## 共用结构

普通页：

1. 顶部品牌栏：左 MoeGo；右 回门店 / 语言 / 身份头像。
2. 页面导航栏：返回来路 / 当前页标题 / 当前主操作。
3. 内容区：用现有帖子、照片、评论、编辑器或消息组件组合。
4. 适用时固定评论输入栏，预留安全区；软键盘出现时输入栏位于键盘上方，不遮挡目标留言。

动态列表是模块根页，第二行只放标题、消息与发布，不再重复“回门店”。详情、我的、消息保留上下文返回。发布第二行为“取消 / 发动态 / 发布”。

照片大图用深色视图：原 MoeGo 标识放浅色衬底，仍在左上；右侧回门店 / 保存 / 关闭。照片计数另放居中一行，避免在手机宽度挤占标识。关闭返回原页面；回门店直接回游戏首页。

## 页面连续性

- 正文或留言入口：列表 → 详情 → 返回原列表位置。
- 照片入口：列表或详情 → 大图 → 关闭回原页面，不额外生成详情页。
- 消息入口：消息 → 目标详情 / 留言 → 返回消息，保留消息列表位置。
- 我的动态：保留“我发布的 / Slack 同步”的来源页签、列表位置。
- 发布成功：进入新帖详情，返回到发起发布的列表；原页签和浏览位置保留，新帖可见。
- 取消空草稿直接回去；已有文字、照片或上传中时先确认放弃。“回门店”、系统返回共用该判断，并记住本次点击的离开目标。
- 上传 / 发布失败保留输入和已选照片，重试不制造重复帖子。
- 弹层先关闭自身并还原焦点；系统 / 浏览器返回与页面返回保持同一层级。
- 深链接没有来路时返回动态列表；未登录先复用现有 PIN 流程，成功回原目标。
- “查看 Slack 原帖”作为外部入口，不清空站内位置。
- 来源已删除时展示通用移除态，保留返回入口，不展示缓存敏感内容。

## 快捷栏与新评论图标

前四个图标来源：独立 checkout 中已选定的 pet-paw-icons-playful-v1。确认来源见其设计记录及 assets/icons/pet-paw-icons-playful-original-v1/README.md。

- paw-cute：蓝猫与小爱心，对应“被你萌到了”。
- paw-pets：小爪摸蓝猫，对应“想摸摸头”。
- paw-play：小爪推橙球，对应“想和你玩”。
- paw-love：小爪抱橙心，对应“给你比个心”。

为避免 checkout 后续清理导致引用失效，四枚现有母版逐字节复制到本目录 sources，仅用于评审。manifest.json 记录来源、SHA256 和字节一致性。本轮没有修改来源 checkout、现有图标库或导出文件。

评论新稿使用奶油白气泡、橙色三点、炭黑轮廓与小爪。透明度已检查，alpha 范围 0–255。它是待评审原图，尚未接入正式 Icon。

手机快捷栏规划为一行五项，16px 侧边距后约 358px 可用；前四项图标加计数，最右项评论，轻分隔。完整语义用于可访问名称及提示，图例不强塞到帖子内部。数字过长时显示本地化紧凑数字，完整数量仍可访问。正式 390 × 844 布局需实现后验证。

图中选中项仅说明外观，不代表新确定了“互斥 / 可多选 / 次数”等产品规则；本轮没有修改动态后台的旧三种类型，也没有改变宠物爪印簿或永久玩家点赞的规则。

## 边界状态

- 空态仍有发布入口，加载用骨架，错误保留重试。
- 站内帖子删除：照片和本站留言一起移除，明确不可恢复。
- Slack 同步帖子：只在本站隐藏，原帖保留。
- 其他人内容：保留问题反馈。
- 管理操作失败留在原弹层，不丢输入。
- 原帖移除清理旧正文、照片和敏感通知预览，提供来路返回。
- 登录复用现有 PIN，不再设计第二套 Slack 验证。
