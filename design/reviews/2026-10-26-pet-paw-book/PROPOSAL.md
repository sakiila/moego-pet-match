# 宠物爪印簿

日期：2026-10-26。状态：用户已认可文字方案与 v2 视觉方向，并明确要求继续实现。本地功能已接入，进度、验证与上线前迁移要求见 [IMPLEMENTATION](IMPLEMENTATION.md)。已完成本地实现与验证，尚未推送或发布。

## 目标与范围

已收集宠物的同事留一句固定短句，主人主动代宠物回一个爪印。留下时立即获得可见反馈，主人的回应成为之后回访的理由。玩家点赞继续表示对玩家的认可，宠物爪印单独记录。

首版包含宠物详情入口、固定短句、主人回爪、游戏内新互动提示及必要的失败与退出状态。一次交流为一条留言和一次主人回应。沿用当前选择同事身份的参与方式，不把姓名头像解释为经验证的个人登录。

## 已认可的规则与本轮边界细化

| 项目 | 约定 |
| --- | --- |
| 对象 | 当前上架的普通宠物；同一宠物在所有入口共用状态，不按模式或日期拆分 |
| 留言资格 | 当前有效同事已收集该宠物，且不是该宠物的主人 |
| 查看资格 | 当前有效同事已收集该宠物，或为宠物主人；未收集的其他同事只见解锁说明 |
| 展示身份 | 显示留言时所用同事身份的当前姓名、头像与选定短句，不展示邮箱 |
| 留言数量 | 同一身份对同一宠物最多一条有效留言，可换短句或撤回，按有效留言身份去重计人数 |
| 留言内容 | 被你萌到了 / 想摸摸头 / 想和你玩 / 给你比个心；已按用户意见去掉“下次还点你” |
| 主人回应 | 当前主人主动点击“回个爪”；每条有效留言最多一次，显示“{owner} 代 {pet} 回了一个爪印” |
| 回应权限 | 服务端核对当前主人；前端按钮状态不代替权限检查；缺少有效主人时仍允许有资格的同事留言，回应入口不出现 |
| 换短句 | 修改当前表达，不新增人数，不改变留言排序时间，也不制造新提醒；已有通用回爪仍适用 |
| 撤回 | 留言与关联回应一起退出展示、计数与未读提醒；再次留言只恢复一份有效留言，旧回应不自动恢复 |
| 防重复提醒 | 同一身份对同一宠物仅首次留言产生主人提醒、首次收到回爪产生自己的提醒；修改、重复请求及撤回重留不重置提醒资格 |
| 统计 | 认识人数、有效留言人数、玩家收到的赞分别统计；分数、排名、阵容、收集和称号规则沿用既有约定 |
| 下架与删除 | 宠物下架后簿、预览和提醒一并不可见；正式删除清理覆盖留言、回应与提醒记录；删除同事资料也覆盖其互动记录 |
| 名册变动 | 不再有效的同事不出现在公开留言与人数中，也不能继续互动；提示与簿使用相同过滤条件 |

爪印簿是独立的主动互动名单，不扩展原“认识人数”区域的名单能力。主人回复是本人主动操作，不由系统自动冒充主人发送。

## 页面与交互

### 宠物详情入口

现有卡片整面点击会翻转，因此将入口放在卡片下方独立动作行，视觉靠近详情卡，但不嵌入翻转操作区域。保持贴纸、主人、认识人数与翻面图标的现有层级。

- 已收集、未留言：留个爪印。
- 已收集、已留言：已留爪印；仍可打开簿、修改或撤回。
- 主人：看看爪印；不显示给自家宠物留言的选项。
- 未收集的他人宠物：收集 TA 后，可以留个爪印；不返回留言人数、留言者、回应或未开放的主人信息。
- 下架、详情加载中或读取失败：沿用对应详情状态，不显示可提交的爪印入口。

入口出现在所有既有宠物详情来源，包括图鉴、报告的新收集卡、玩家名片及我的宠物。鱼本身不是普通宠物目录项，不新增鱼留言入口。

### 同事视角的爪印簿

使用现有白底圆角 Sheet 风格，顶部为小宠物贴纸、名字、标题“爪印簿”和关闭按钮。主体只在簿内滚动。固定短句使用 2 × 2 按钮，点选即提交；服务端确认后才显示成功与选中状态。

未留言时显示“给 TA 留一句”；已留言时显示“你的爪印”，选中短句高亮，并提供“撤回”。四个选项保持可见，点另一项即“换一句”，无需额外编辑页面。自己的回应紧跟这块展示；下面按首次留言时间倒序显示其他同事的记录，初始三条、原位展开更多。人数包含自己的有效留言，但自己的内容只展示一次。

首次发送成功，入口与选择同步更新，并播一次小爪印落下的短动效；“减少动态效果”时只更新状态。没有主人回应时保留完整的已留言状态，不把回应当作领取条件。

### 主人视角的爪印簿

同一份簿改为查看留言，隐藏四个留言选项。每条未回应记录右侧为“回个爪”，已回应显示“已回爪”；新留言带简洁“新”标记。回爪也需服务端确认后才更新。主人无需选择三套回复文案或输入文字。

### 关闭与返回

簿打开时保留底层宠物详情和来源页面的滚动位置，并暂停底层交互。关闭、点遮罩或 Escape 只关闭最上层，焦点回到爪印入口；之后再关闭宠物详情才回到原图鉴卡或名片。长英文名自然换行，不挤压关闭按钮；触摸目标至少 44 × 44 CSS px。

## 新互动提示

| 事件 | 首页入口 | 页面内定位 |
| --- | --- | --- |
| 自家宠物收到首次新留言 | 我的宠物出现小圆点 | 对应宠物卡标记“新爪印”，点击打开详情及该宠物爪印簿 |
| 自己的留言首次得到回应 | 图鉴出现小圆点 | 图鉴顶部展示“{pet} 的主人回了你一个爪印”，点击打开并定位自己的留言 |

两类提示对有宠物、没有宠物的玩家都适用。多条回应可在图鉴顶部逐条查看，不另建通知中心。只在游戏内提示，不增加 Slack 消息或浏览器通知。

进入门店、进入对应页面、打开簿及页面重新可见时刷新，采用请求时更新即可。首页和列表只读不标已读；簿实际呈现相应留言或回应后，按本次看见的事件 ID 确认已读。新到达且尚未看见的事件保留未读；分页未呈现的记录不提前清除。已撤回、已下架或不可见的事件不再点亮入口。

## 工程与验证落点

1. 独立保存宠物留言关系、当前固定语义、回爪与已读状态。数据库保证 `(pet_id, player_id)` 的逻辑唯一，首次互动资格保留用于防止撤回重留刷提醒；撤回后公开内容与回应不可见。正式资料删除执行真正清理，不把撤回视为永久保留资料的授权。
2. 所有读写在服务端核对上架、有效同事、当前收集与主人权限。提交锁定或串行处理同一关系，并在事务内核对状态；重试、并发留言、并发回爪和撤回竞争均返回权威当前状态。旧请求不能覆盖后来一次修改。
3. 为共享 PetDetailOverlay 增加独立入口和簿组件；提醒分别接入现有首页导航、我的宠物和图鉴。组件经 props 获取数据与文案，样式复用 tokens，全部状态登记 Gallery。旧翻转交互与层叠返回作为回归重点。
4. 上线前在 UI_COPY 和双语信息说明补充：固定短句、同事身份、主人回应及其可见范围；同步 V1_RULES / GAME_FLOW。预览稿不扩大正式选定素材或切图授权，界面控件继续用 CSS / SVG 和统一 Icon，宠物使用正式贴纸。
5. 服务端测试覆盖资格、上架变化、同事失效、自家禁留、四种合法语义、重复与并发、修改、撤回重留、回应权限和幂等、未读确认竞争、资料清理。前端验证发送失败与重试、0 / 多条、长姓名、中英文、鱼主题下纸面、减少动态效果、390 × 844 与横屏、翻面和三层弹层焦点。

效果验证优先看留爪印的访客比例、给主人看到的新留言中有多少得到回应、收到回应的玩家是否回来查看。初期不把累计留言数量作为留存提升的证明。

已目视核对：三种视角同属一只宠物与同一主人；四句短句含“想和你玩”、不含已退回的点单文案；详情的独立入口、同事的已选与撤回、主人的两条待回应和一条已回爪均出现；18 位认识者和 12 位留爪印者为不同的示意指标。v1 背景误带了参考截图里的“查看 Bob 的玩家名片”测试按钮，v2 用内置 ImageGen 定点移除，保留原稿和请求记录。

两版实际输出均为 1536 × 1024 三列对照图，未按提示词请求的约 2560 × 1920 输出；每列为手机布局示意，不能替代精确 390 × 844 的浏览器截图。图中的小符号、开发者章和贴纸仍为生成近似，实装复用正式素材或按组件约定实现；英文、空态、加载、失败和真实焦点行为须在实现时另行验收。

最初设计阶段只增加方案、请求留档和视觉稿。用户后续授权实现后的代码、迁移与浏览器验收见 IMPLEMENTATION；现有宣传片相关改动保持原样。生产环境尚未变更。
