# 宠物爪印簿 · 实现与验收

日期：2026-10-26。用户已认可 [v2 方向](../../concepts/pet-paw-book-v2.png)并要求继续。当前为本地可用版本，本次提交包含爪印簿及后续收集提示文案调整，尚未推送或上线。

## 实施顺序与结果

1. 先写服务端行为测试，再新增 `018_pet_paws.sql`、独立服务和路由；唯一身份关系、修订版本、撤回、主人回应和已读状态共同保证并发与重试幂等。
2. 接入共享宠物详情下方的独立入口与 PawBook，覆盖图鉴、局后新收集卡、我的宠物和玩家名片。底层宠物卡和名片保持挂载，上层打开时暂停交互，逐层关闭并恢复焦点。
3. 首页在我的宠物 / 图鉴入口标记新互动；对应页面直接定位宠物爪印簿。只有前台实际可见的留言或回应才按 ID 确认已读，普通读取、未展开记录和后来到达的记录不清除。
4. 文案与数据使用语义 ID；双语信息说明同步补充留言、回应和已读状态及可见范围。V1_RULES、GAME_FLOW、UI_COPY、DESIGN_NOTES 与本方案保持一致。
5. 新 UI 以 props 驱动，沿用 tokens、Sheet、Avatar 和统一 Icon。五个简单图形使用原生 SVG，宠物与既有勾选、翻面等素材继续复用正式资源，没有从概念截图切控件。

## 后端边界

- 已收集的有效非主人可留四种固定短句；主人无需先收集即可看簿和回爪，不能给自家宠物留言；其他人读取与提交均拒绝。
- 一人一宠一条有效关系。更换不变首次排序时间，撤回清除可见留言与回应，重留不恢复旧回应、不重置首次提醒资格。
- 同宠物写入使用事务锁；修改带版本，旧请求不覆盖新状态。回应、撤回和重复提交使用同一条权威关系。
- 临时下架立即隐藏内容；正式墓碑下架在数据库触发器内清理互动。正式删除同事时外键和触发器清理其留言与回应。日常停用仅从展示、计数和提醒中排除。
- 上下架脚本在数据库行锁前取得相同的宠物锁，避免清理与新留言的锁顺序冲突。没有执行生产上下架操作。
- GET 使用稳定游标分页；已展开旧页后回爪，请求保留已加载条数，避免回应成功后突然缩回首页。每次修改返回服务端确认的状态。
- 爬取或切换身份的边界沿用既有选择同事身份机制，不宣称经过 Slack 身份验证。

## 验证环境

浏览器使用 `http://127.0.0.1:5181/`，服务端 `127.0.0.1:8788`，独立本地 Postgres 开发库 `pet_match_paws_20261026`。现有 5180 / 8787 服务未被替换。样例为测试身份与正式宠物贴纸；头像使用本地字母占位，不请求 Slack。

Browser 插件与其 `browser` skill 不在会话能力列表，采用已安装运行时的 Playwright + Chromium 验证，没有安装新的浏览器依赖。测试目标为“宠物详情 → 固定短句 → 主人收到并回爪 → 留言者从提示查看回应”。临时脚本、截图、日志位于 `/tmp/moego-paw-qa/`，不属于提交源码。

## 与图稿的对照

- 保持橙白配色、独立下方入口、2 × 2 短句、个人回应区、主人回爪和白底 Sheet 的信息层级。
- 实装复用原有整张卡片翻转、边框流光与开发者章；概念图中的生成近似没有替换这些正式素材。
- 姓名与宠物名按真实字段完整显示，不擅自把 `Maodu 毛肚` 改成昵称；英文长名自然折行，回应按钮可占两行。
- 日期使用本地化日期，而非图稿中的示意“刚刚 / 1 小时前”。新标记实际可见并确认后消除，因此静态截图可能已经显示已读状态。
- 桌面与横屏复用最大宽度 480px 的 Sheet，内部可滚动，关闭区保持可见。
