# 开局与成绩防刷

范围仅为 star.baobo.me。用户已选择页面 Managed Challenge，API 使用 JSON 错误、限流和服务端 Turnstile，不对 /api/* 返回整页质询。

## 实现与验收

- Cloudflare：启用本站已知 AI/脚本拦截与页面质询；保留 Slack 分享、API、图片和其他子站现有行为。开局与结算的边缘限流必须限定本站，受免费套餐限制时以源站精准限流兜底。
- 准备页：展示 Turnstile；本站正式 site key 仅用于 star.baobo.me；secret 只保存在运行环境。点击开始时校验单次 token 的 hostname、action 和对局绑定 cdata，网络错误或缺少配置不放行。
- 对局：增加服务端开局时间与私密对局凭证，只接受已验证开局的结果；同一玩家重新开始会作废先前未结算对局。读规则、准备图片均不计时。
- 结算：最多 400 次受理交换，按登记 seed、阵容与操作毫秒时间在服务端重演引擎，核对全部成绩字段；拒绝缺失/篡改记录、过早结算、跨局凭证和旧协议。保持数据库事务及相同内容的幂等重试。
- 限流：先于 Turnstile 和回放执行，分别限制登记、开局、结算；按玩家跨进程共享，避免只靠容易轮换的 IP；返回 429 与 Retry-After，不返回 HTML。
- 验证：单元与数据库集成覆盖 token 成败/超时/重放、并发开局、成绩伪造、时钟与版本、幂等；准备页中英、390×844、错误/过期/重试与正常完整一局。

边界：现有身份是从同事名册选择，并非 Slack OAuth 身份认证。确定性回放可阻止伪造分数，不能证明一份合法操作序列一定由人完成；通过真人验证、按正常速度合法操作的浏览器 Agent 仍可能进入。此轮不自动清理历史成绩，也不更改游戏计分规则。

正式启用前必须完成生产密钥配置与数据库迁移，禁止把测试 key 用于生产或在缺少验证配置时放行。

## 运行参数与发布顺序

1. 在 Cloudflare 创建 Managed widget，仅允许 `star.baobo.me`，无需给其他子站配置或更改 DNS。
2. 在服务器 `production.env` 写入 `TURNSTILE_SITE_KEY` 与 `TURNSTILE_SECRET_KEY`，权限 600；部署预检要求两项存在，应用也会拒绝缺少正式密钥或使用测试密钥的生产启动。
3. 用既有管理员迁移入口先预览，再执行 `018_game_verification`；只为既有 games 表增加验证字段、建立请求计数表，不修改历史成绩。应用角色对新计数表需要读写权限，迁移在角色存在时授予它。
4. 推送并部署新版本，旧页面需刷新。未经过新开局验证的旧局不能加入新成绩；不删除既有排行。
5. 线上验证页面质询、API JSON、真实 widget 的验证/过期/重试，以及正常 90 秒对局保存。未拿到正式 key、未迁移或未真实验证时，不声明线上防刷已完成。

源站限额：单个来源 10 秒 300 次游戏写请求；名单内每位玩家每分钟登记 8 次、开局验证 6 次、结算 20 次。玩家计数保存在数据库，多实例共享，不因应用重启清空。来源突发计数仅作辅助，不能把未经源站网络限制的转发 IP 头当作身份认证。
